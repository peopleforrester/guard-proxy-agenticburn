# guard-proxy-agenticburn

A platform-injected guard proxy for AI agents. It sits between an agent and its model endpoint and
enforces input scanning, output scanning, a hard USD spend cap and fail-closed behavior, for every
workload on the cluster, whether or not the developer who wrote the agent asked for any of it.

Built for the [Unleash an Agent, Watch It Burn](https://github.com/peopleforrester/Unleash_an_Agent_Watch_It_Burn)
workshop, where it is the control attendees switch on while an agent is being attacked.

## Status: being rewritten in Go

`proxy.py` is the **reference implementation**: 1,295 lines of Python with no third-party
dependencies, tuned against live attacker behavior across two workshop deliveries. It is what runs in
the workshop today.

It is being rewritten in Go, because it is expected to become a product and Go's libraries suit a
network proxy better than Python's `http.server`. The rewrite also folds in what LiteLLM does better.
The main example is LiteLLM's budget reservation, which estimates a request's maximum cost and rejects
it **before** the model is called. `proxy.py` meters cost after the response arrives, so it can only
block the *next* request, and so can agentgateway's budgets. Tracked in
[Unleash_an_Agent_Watch_It_Burn#412](https://github.com/peopleforrester/Unleash_an_Agent_Watch_It_Burn/issues/412).

### The Go implementation so far

| Milestone | State |
|---|---|
| M0 conformance suite | done |
| M1 skeleton: listener, agent forwarding, config validation, health | done: passes the `passthrough` conformance subset |
| M2 guards on the A2A path: block-list, LLM Guard classifier, output guard, fail closed | done: passes the `guards` conformance subset |
| M3 budget reservation: count tokens and cap `max_tokens` before the model is called | the embedded store is done: spend survives a restart (#32). The reservation is not started; it needs a design that puts the proxy on the model path (below) |
| M4 rate limits, routing, toggles, the prompt feed | done as `proxy.py` does them |
| M5 telemetry: spans, the cost gauge, log correlation | done: passes the whole suite, spans included, read from a fake OTLP collector |
| M6 signed image, M7 live validation | not started |

M3 as the PRD writes it is not a port. guard-proxy sits in front of the agent (`AGENT_URL`, kagent),
not in front of Bedrock, and reads a turn's token usage from the agent's reply after the fact, so it
never holds a model request it could count or cap. The Go build therefore meters spend after each
reply, exactly as `proxy.py` does, and the reservation waits on a design for that hop.

```
go test ./...                                   # unit tests, plus an end-to-end test of the binary
go build -o bin/guard-proxy ./cmd/guard-proxy
AGENT_URL=http://localhost:3000 LLM_GUARD_URL=http://localhost:8000 SPEND_STORE_PATH=/tmp/spend.db bin/guard-proxy --listen 127.0.0.1:8080 [--config guard-proxy.yaml]
bin/guard-proxy reset-spend --store /tmp/spend.db      # with the proxy stopped: the next start is at $0
```

It serves every endpoint `proxy.py` does, with the same guards, limits, caps, toggles and prompt feed
on both paths, emits the same spans, cost gauge and trace-correlated logs, and passes the whole
conformance suite. `proxy.py` stays what the workshop deploys until the cutover after KubeCon
(2026-11-12), which waits on the signed image (M6).

Telemetry is exported over OTLP/HTTP from the standard environment, the variables the OTel Operator's
`instrumentation.opentelemetry.io/inject-sdk` annotation sets: `OTEL_EXPORTER_OTLP_ENDPOINT`,
`OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES` and the rest. With no OTLP endpoint and no
`OTEL_TRACES_EXPORTER=otlp`, it is off, as `proxy.py` is without the SDK, and the startup log says so.
The W3C context is propagated either way. Span and metric attribute names are generated by weaver
from the workshop's registry (`scripts/gen-semconv.sh`).

Where it differs from `proxy.py` on purpose:

- A scanner failure logs a `guard_error` event at WARNING before the request is refused (or, with
  fail-closed off, allowed). `proxy.py` fails silently.
- `PROXY_FAIL_CLOSED` accepts only `true` or `false`; anything else stops startup. `proxy.py` reads
  any value but `true` as false, so a typo turns fail-closed off.
- With no `LLM_GUARD_TOKEN`, no `Authorization` header is sent, rather than an empty bearer token.
- A request body of an unexpected shape carries no text, so no input guard applies to it, and an
  unexpected reply shape is passed through. `proxy.py` raises on both and drops the connection.
- A reply the output guard leaves alone is returned byte for byte. One it changes is re-encoded, with
  keys in sorted order.
- A scanner failure on the topic classifier or on `/chat` logs `guard_error` too.
- A spend setting `proxy.py` would crash on or silently switch off, such as `COST_CAP_USD=-1`,
  `RATE_LIMIT_RPM=1.5` or `COST_PER_1K_IN=` (empty), stops startup. An empty cap or limit still means
  its default, as in `proxy.py`.
- Telemetry exports OTLP over http/protobuf only. `OTEL_EXPORTER_OTLP_PROTOCOL=grpc`, or an
  `OTEL_TRACES_EXPORTER` or `OTEL_METRICS_EXPORTER` other than `otlp` or `none`, stops startup.
- The caller's `traceparent` is read case-insensitively. `proxy.py` joins it only when the header name
  arrives lowercase, as agentgateway sends it.
- `error.type` on a failed forward, `/chat` or A2A, is the HTTP status code, `timeout`, or `_OTHER`,
  per the HTTP conventions. `proxy.py` records the Python exception's class name.
- Whole-word matching in the profanity list and the topic phrases uses RE2's ASCII `\b`, where Python's
  is Unicode-aware. A term next to a non-ASCII letter ("fuckñ") is masked in Go and not in `proxy.py`.
- The cost tally, each session's spend and the `/toggle` cost cap are kept in a bbolt file at
  `SPEND_STORE_PATH` (`spend.store_path`), so a restart, a crash or an OOM kill does not reset spend.
  `proxy.py` keeps them in memory and a restart zeroes them. The path is required, and one the process
  cannot open for writing, or that another process holds, stops startup. Each reply's spend is committed
  before the reply is returned; if the commit fails the reply is withheld (`/chat` answers its 502, the
  A2A path a 502 with the error) and `spend_store_error` is logged. Reset in the storefront still means
  a fresh session, which has no stored spend. To start a new delivery from $0, scale the proxy to 0 and
  run `guard-proxy reset-spend --store PATH` from the same image with the volume mounted: it clears the
  tally, every session's spend and the `/toggle` cost cap, keeps the file, prints what it cleared, and
  refuses a store the proxy still holds or a path with no store. No HTTP endpoint resets spend. See
  [decisions.md](decisions.md) for why.

Config is one YAML file, decoded strictly: an unknown key stops the process at start.

```yaml
listen: ":8080"            # default; --listen overrides it
agent:
  url: http://agentgateway.agent.svc.cluster.local:3000   # required
  timeout: 150s            # default; bounds the whole upstream exchange
llm_guard:
  url: http://llm-guard.agent.svc.cluster.local:8000      # required
  timeout: 150s            # default; the token comes only from LLM_GUARD_TOKEN
chat:
  turn_timeout: 0s         # default, no turn deadline; bounds every upstream call of a /chat turn
blocklist: [delete, "rm -rf"]   # replaces the default list; terms are trimmed and lowercased
fail_closed: true          # default; refuse when LLM Guard gives no verdict
guards:                    # the state each guard starts in
  input_blocklist: false
  input_classifier: false
  output: false
  budget: false
  topic: false
spend:
  cost_cap_usd: 0          # default, off; the cluster-wide backstop
  budget_cap_usd: 0.03     # default; the per-session cap the budget guard enforces
  rate_limit_rpm: 0        # default, off; model-bound requests per minute, both paths
  rate_limit_session_rpm: 0   # default, off; per /chat conversation, checked first
  model_tier: haiku        # default; nova, haiku, sonnet or opus; the start-up tier (see below)
  # model_name, cost_per_1k_in and cost_per_1k_out default from the tier; a price set here is fixed
  store_path: /var/lib/guard-proxy/spend.db   # required (or SPEND_STORE_PATH); on the pod's volume
feed:
  enabled: false           # default; GET /prompts records nothing until this is on
  profanity: [cilantro]    # replaces the default list; whole words, plural included
topic:
  off: [karaoke, hot dog]  # refuses without a model call
  on: [menu, burrito]      # passes without a model call; anything else goes to BanTopics
  refusal: "BurritoBot only talks burritos: the menu, our hours, and our locations."
cors:
  console_origins: [https://start.agenticburn.com, https://start.burritobot.co]   # default
controls:                  # the in-cluster defaults; override to point at another API server
  api_url: https://kubernetes.default.svc
  token_path: /var/run/secrets/kubernetes.io/serviceaccount/token
  ca_path: /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
  public_host: ""          # reported by /controls as "host"
telemetry:
  capture_content: false   # default; gen_ai.input/output.messages carry prompts and replies when on
  peer_service: burritobot-gateway   # default; names the agent hop on agent.forward spans
```

Every environment variable `proxy.py` reads (listed under [Configuration](#configuration)) overrides
the file, with the same meaning, and `SPEND_STORE_PATH` sets `spend.store_path`. The guard switches and
`STREAM_PROMPTS` are on only for the value `on`, as in `proxy.py`. Read [docs/gotchas-go.md](docs/gotchas-go.md)
before changing the upstream hop or adding a dependency.

## What it does

| Function | How |
|---|---|
| Input scanning | Calls an LLM Guard API server running a prompt-injection classifier, plus a local blocklist |
| Output scanning | Regex over the completion for planted secret patterns; blocks and redacts |
| Spend cap | Per-session and per-cluster USD caps, metered from token usage |
| Rate limiting | Requests per minute |
| Model tier | Routes to a cheaper or more expensive model by config |
| Fail closed | If the scanner is unreachable, refuse rather than pass through |
| Telemetry | OpenTelemetry spans with gen_ai attributes, including message content when enabled |
| Live prompt feed | Streams prompts to a feed the room watches during the workshop |

The last row is workshop apparatus rather than a product feature, and nothing else in the ecosystem
provides it.

## Configuration

Everything is set through environment variables:

```
AGENT_URL  BLOCK_LIST  BUDGET_CAP_USD  BUDGET_GUARD  CONSOLE_ORIGIN  COST_CAP_USD  COST_PER_1K_IN
COST_PER_1K_OUT  INPUT_BLOCKLIST  INPUT_CLASSIFIER  INPUT_GUARD  K8S_API_URL  K8S_TOKEN_PATH
LLM_GUARD_TOKEN  LLM_GUARD_URL  MODEL_NAME  MODEL_TIER
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT  OUTPUT_GUARD  PEER_SERVICE  PROFANITY_LIST
PROXY_FAIL_CLOSED  PROXY_TIMEOUT  RATE_LIMIT_RPM  RATE_LIMIT_SESSION_RPM  STREAM_PROMPTS
TOPIC_GUARD  TOPIC_OFF_LIST  TOPIC_ON_LIST  TOPIC_REFUSAL  TURN_TIMEOUT  WIB_PUBLIC_HOST
```

`PROXY_TIMEOUT` bounds each upstream call. A `POST /chat` turn can make up to seven in a row: the
injection classifier, the topic classifier, the forward, the three self-heal retries and the output
scrub. `TURN_TIMEOUT` (seconds, default `0` for none) is one deadline for the whole turn: each call
gets `PROXY_TIMEOUT` or what is left of the turn, whichever is less, and a turn that runs out
answers the same 502 as a failed forward. A guard call the deadline cuts off ends the turn with
that 502 whatever `PROXY_FAIL_CLOSED` says, so fail-open never forwards an unscanned prompt or
returns an unscrubbed reply. The thinking-only retry is optional, so running out of time on it keeps
the first reply, as its failure does. The A2A path is not bounded by it.

Each self-heal retry re-sends the prompt once, never in a loop, and every attempt is metered. A reply
that is Bedrock's dangling `tool_use` error rotates the session to a fresh contextId first (`ctx_rotate`).
A reply that is Bedrock's 424 `ModelErrorException ... invalid sequence as part of ToolUse`, the model
breaking the tool-call grammar, is re-sent in the same conversation (`model_error_retry`, #62); a second
424 is the reply. A reply that is only the model's scratchpad is re-sent (`thinking_only_retry`), and
when the retry fails or is also reasoning-only the turn surfaces the scratchpad's contents.

The `/chat` forward is an A2A task (#27). It is sent as a non-blocking `message/send`, which answers
with the task's id, and polled with `tasks/get` until the task leaves `submitted` and `working`.
`PROXY_TIMEOUT` bounds the whole forward, every poll included. When the forward fails or runs out of
time with a task still running, the turn answers its 502 and guard-proxy then sends the agent
`tasks/cancel` for that task, logging `task_cancel`, or `task_cancel_failed` when the agent refuses or
cannot be reached. kagent runs a turn detached from the request, so without the cancel a turn nobody
is waiting for keeps calling tools and the model.

A `/chat` body can carry `witch`, the visitor's name the storefront assigns (#34). When it is shaped
like a storefront name, `<First> the <Creature>` with each word capitalized and at most 16 letters (#35),
the A2A message gets a second text part after the prompt, `The person chatting with you gave their name
as <name>.`, so the agent knows who it is talking to. No guard scans the name and it never goes into the
prompt's text, on the agent's message or on the prompt feed. Without one, or with a name of any other
shape (logged as `witch_name_refused`), the message is exactly the prompt.
The same name rides as an `X-Witch-Name` header on the message/send and on every tasks/get poll (#64), so
kagent can copy it onto the agent's MCP calls and workshop-mcp credits a deploy to the visitor from the
request rather than from the model. Without a name there is no header, and `tasks/cancel` and the A2A
passthrough never send one.

`GET /prompts` answers `{"enabled": bool, "prompts": [str], "witches": [str]}`. `prompts` is the last 50
moderated prompts, oldest first, as bare strings. `witches` is as long as `prompts`, and `witches[i]` is the
witch name of whoever sent `prompts[i]` (#59), so the prompt wall can label each prompt with its sender.
A prompt with no name carries `""`, never null and never a shorter list: a `/chat` with no `witch`, or a
blank, non-string or misshaped one, and every A2A prompt. A name the feed's moderation would change in any
way (personal data, a block-listed or profane word) is dropped whole, to `""`, rather than shown half
masked. The names ride beside the texts rather than as `{text, witch}` objects because three readers parse
`prompts` as strings, and a second copy of each text would push a full feed of emoji prompts past
lab-platform's 256 KiB read.

Once a guest message that reaches the agent asks what files or folders the bot can see or has access to
(such as Challenge 3's `What folders do you have access to in your file system?`), the proxy marks that
`session`, and every later message in it gets one more text part after the name: `[kitchen note: earlier
in this chat the guest asked what folders you can see]` (#63). The workshop Agent's recipe rule is keyed on
that exact text. The question itself carries no note, a Reset (a new `session`) clears the mark, and the
self-heal contextId rotation keeps it. Like the name, no guard scans the note and the prompt feed does not
show it.

The proxy also keeps the recipe card's pantry shut in a chat that may not have the card (#65). Per
`session`, it notes whether any guest message has named `burrito-data`, `config/legacy` or
`secret-sauce-recipe`, and whether a reply named `burrito-data` or `secret-sauce-recipe` before the guest
did. Once a reply did, every later turn's message/send and tasks/get polls carry `X-Pantry-Shut: shown`;
otherwise a message naming none of the three carries `X-Pantry-Shut: unnamed`, and one naming any carries
no header, so a fresh chat's Challenge 3 attack still reads the card. kagent copies the header onto its MCP
calls, and workshop-mcp withholds the recipe on any call that has it. tasks/cancel and `/a2a` never carry
it. A Reset starts clean; the self-heal contextId rotation keeps the state, and a restart clears it.

`COST_CAP_USD` (default `0` for none) is the cluster-wide backstop on spend. `GET
/toggle?cost_cap=2.00` lowers it at runtime, keeping the tally an env change would reset, and
`/toggle?cost_cap=default` restores the env value. A runtime cap must be above 0 and no higher than
`COST_CAP_USD` while that is set; anything else answers 400 and changes nothing. `/toggle` reports
the cap in effect as `cost_cap_usd`, and `/cost`'s `cap_usd` counts it. When it trips, `/chat` says the
whole kitchen is closed and stamps `witb.guard.decision` as `cost_cap`, since Reset cannot lift it; the
per-session budget cap's reply offers Reset and stamps `budget`. The cluster-wide cap answers first when
both have tripped.

Every `/toggle` that changes a guard or the cost cap logs one `guard_toggle` INFO line per change (#67), in
the order the answer lists the keys, so a guard found in the wrong state can be traced to the request that
set it. Each line carries `guard`, `value` and `was` (a bool, or the cap in dollars), `peer` (the TCP
client's address, `127.0.0.1` for a `kubectl exec` into the pod) and `caller`, the `X-WIB-Caller` header the
workshop's scripts send to name their run, cut to 200 characters (bytes in the Go build) and `""` when
absent. The message reads `guard output set to true by 127.0.0.1 (kubecon_probe.py admin pid 7 in ...)`. A
`/toggle` that changes nothing, an unknown key and a refused `cost_cap` log nothing.

Each request is priced at the model the `workshop-agent` Agent is bound to (#37), so a live patch of its
`spec.declarative.modelConfig`, which Argo CD leaves out of its diff, needs no `MODEL_TIER` change.
guard-proxy reads the Agent with the same get-only token as `/controls`, at most every 5 seconds, and a
ModelConfig `bedrock-<tier>` prices at that tier: `bedrock-nova`, `bedrock-haiku`, `bedrock-sonnet` or
`bedrock-opus`. `MODEL_TIER` prices requests until the Agent has been read, and whenever it names any
other ModelConfig, such as `gateway-local-qwen3`. A read that fails keeps the tier the last read found.
Each change of binding is logged once, as `price_tier`, or as the warning `price_tier_unknown` for a
ModelConfig with no tier. `/cost` reports the tier in effect as `tier`; spend already metered keeps the
price it was metered at. `COST_PER_1K_IN` and `COST_PER_1K_OUT` each fix their price whatever the
binding.

`gen_ai.request.model` follows the same binding (#38): the A2A `sanitize` span, the `/chat` root and
`chat` spans report the model ID of the tier the request is priced at, such as
`us.anthropic.claude-opus-4-8` for `bedrock-opus`, and `MODEL_NAME`, when set, is reported instead
whatever the binding. The cost gauge `gen_ai.client.cost` has one series per `gen_ai.request.model`,
each what that model has spent, so the series add up to `/cost`'s `usd`; query it with `sum:`, not
`max:`, to read a cluster's bill. The model bound now always has a series, at $0 until it spends. The Go
build keeps the split in its spend store, and refuses a store written before it with spend on it (clear
it with `guard-proxy reset-spend`).

The `/chat` `chat` span carries the turn's `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`
(#49), summed over its forwards, self-heal retries included: the totals the storefront is sent, and what
Datadog's Agent Observability reads an llm span's tokens from. The `/chat` root and the A2A `sanitize`
span carry none, because the collector turns those into Agent Observability's `invoke_agent` span, where
the counts would sit beside kagent's own.

A `/chat` turn whose forward fails and answers 502 is an error on the root and the `chat` span as well as
on `agent.forward` (#53), so a Datadog error rate or the Agent Observability list counts a timed-out turn
as failed. A failed reasoning-only retry, where the turn still answers 200 with the first reply, leaves
the root and `chat` span Unset; only that retry's `agent.forward` span is an error.

A failed A2A forward is an error on its `sanitize` span too (#61), with the same `error.type` as
`agent.forward` and no status code of its own. The workshop collector makes `sanitize` that turn's root
in Agent Observability and drops `agent.forward`, so without it a failed turn reads as green.

Every POST answered with a 5xx is an error on its `POST <path>` server span (#54), as OTel's HTTP
conventions have it: a failed A2A forward, a `/chat` turn whose guard stage ran out of `TURN_TIMEOUT`,
and, in the Go build, a reply withheld because the spend store did not commit its spend. The span's
status description names what failed. A 4xx or a guarded 200 leaves it Unset. GET requests, the
discovery passthrough and the admin endpoints included, have no server span in either build, so their
5xx answers are in the logs only.

Several overlap (`BUDGET_CAP_USD` and `COST_CAP_USD`, `INPUT_GUARD` and `INPUT_CLASSIFIER`). Some of
that is history and some is a live toggle the workshop flips. Rationalizing them is part of the
rewrite.

## Endpoints

| Path | Purpose |
|---|---|
| `POST /chat` | The proxied agent call, with every guard applied |
| `GET /cost` | Current spend against the active cap |
| `GET /prompts` | The live prompt feed, with each prompt's witch name in `witches` |
| `GET /guards` | Which guards are on |
| `GET /controls` | The state of each workshop challenge's control |
| `GET /toggle` | Switches a guard, or sets the cost cap, live without a restart |

## Conformance suite

`conformance/` is a black-box HTTP test suite. It is the contract the Go rewrite has to meet. It
starts the implementation as a subprocess and points it at real local servers that stand in for the
agent and the LLM Guard API. It then checks only what a client could observe: status codes, response
bodies, headers, what reached each upstream, and the structured log events. No test imports the
code under test.

```
uv run pytest                                          # against proxy.py
GUARD_PROXY_CMD="$PWD/bin/guard-proxy --listen 127.0.0.1:{port}" uv run pytest   # against the Go build
uv run python conformance/mutation_check.py           # negative control, see below
```

`GUARD_PROXY_CMD` is the only adapter. `{port}` is replaced with 0: the implementation binds a free
loopback port itself and logs `listening on 127.0.0.1:<port>`, and the suite waits for `GET /guards` to
answer there. A port the suite picked and released first could be taken by another process on a busy
host before the implementation bound it.

Both implementations run the whole suite. The span tests (`-m spans`) start a fake OTLP/HTTP collector
and point the implementation at it with `OTEL_EXPORTER_OTLP_ENDPOINT`, so they read what production
exports rather than a test-only file; `launch_python.py` installs the OTLP exporters for `proxy.py` as
the OTel Operator does. The `passthrough` and `guards` markers still select the M1 and M2 subsets.

The suite covers:

- every endpoint;
- both input stages, the output guard, and fail-closed against an unreachable, erroring, malformed or
  slow scanner;
- the rate limit, the cluster-wide cost cap and the per-session budget cap, and the order they run in;
- token metering, and pricing at the model the Agent is bound to, through a live swap;
- the self-heal retries;
- the `/chat` task poll and its `tasks/cancel` on a failed or timed-out forward;
- the moderated prompt feed;
- response CORS.

`mutation_check.py` runs the suite against deliberately broken copies of `proxy.py`, and fails
unless every one is caught. That is how we know the suite pins real behavior and does not just
pass.

**Not covered yet.**

- **Telemetry against Datadog.** The suite pins what is exported, not what Datadog makes of it; the
  PRD's live check (LLM Observability panels, root-span count against the recorded baseline, #320 in
  the workshop repo) still needs a cluster.
- **`/controls` against a cluster API, for C1, C3 KubeArmor and C8.** `K8S_API_URL` and
  `K8S_TOKEN_PATH` point `proxy.py` at a fake API server, and the C2 Kyverno ValidatingPolicy, C3
  Falco DaemonSet and C7 badges are tested that way. The C1 NetworkPolicy, C3 KubeArmor and C8
  `rbac_scoped` badges are tested only in the no-credentials case.

**Known defects are pinned, not hidden.** A test whose name ends in `_today` asserts current behavior
that is wrong, and names the issue that tracks it (#1 through #4). Fixing one changes `proxy.py` and
that test together.

## How the workshop consumes it

The workshop repository includes this one as a git submodule at `gitops/ai-layer/guard-proxy/`. A
kustomize `configMapGenerator` turns `proxy.py` into a ConfigMap, which is mounted into a stock Python
image. That delivery is what lets a code change reach a live cluster in seconds during the workshop.
[docs/release-notes.md](docs/release-notes.md) names the commit to repin the submodule to for each change.
The Go rewrite replaces it with a signed, digest-pinned image.
